# Context

## Glossary

| Term | Definition |
|------|-----------|
| Booth Phone | The street-level landline phone connected via the Grandstream HT814 gateway. Callers pick this up. |
| Upstairs Phone | The Yealink T46G SIP phone upstairs that rings when a caller succeeds. Signals the operator to drop pizza. |
| PBX | The Asterisk PBX running on the Mac Mini (Debian) that routes calls between the two phones. |
| Code | The 4-digit PIN callers must dial to succeed. One active code per day. |
| Code Rotation | The act of generating a new Code. Currently done via a bash script (`rotate` command) that sends the code to Slack. |
| Current Backend | Asterisk dialplan configs (`.conf` files) + a bash script. No application backend exists yet. |
| Mode | The method by which callers obtain or earn the Code for a given day. Three modes exist: Tweeted, Audio Puzzle, Roguelike Phone-Tree. |
| Tweeted Mode | The Code is posted publicly (e.g., Twitter/X). Anyone who dials it succeeds. |
| Audio Puzzle Mode | Asterisk plays a `.wav` riddle. The answer is the Code. Caller dials the answer. |
| Roguelike Phone-Tree Mode | An infinitely looping DTMF maze. Caller picks up, navigates branching choices with no lives or attempt limit. Reaching the leaf node has the Code spoken aloud. Caller must then hang up and dial the Code to ring the Upstairs Phone. Tree is regenerated fresh per Call Session. |
| Walk | What one caller did in the Roguelike Phone-Tree: the rooms they stood in, the keys they pressed, and which of the two ways it ended — the Code read out at the leaf, or the caller gone. Rooms *stood in*, so a caller who presses a key that is not a choice replays the room without the walk recording that they were ever anywhere else. |
| Prompt Library | A collection of pre-written spooky scenario prompts (audio or text-to-speech) used as nodes in the Roguelike tree. Authored by the team, not procedurally generated. |
| Puzzle Pool | A set of pre-recorded audio puzzles available for a given day. Callers receive one puzzle from the pool. |
| Attempt Limit | Maximum number of wrong answer attempts allowed per Call Session before disconnection. Set to 3. |
| Exile | The fail-state experience when a caller exhausts all attempts. A flavorful, thematic disconnect message. |
| Operator | The human upstairs who answers the Upstairs Phone and manually drops the pizza via dumbwaiter. |
| Call Session | One pickup-to-hangup interaction on the Booth Phone. May involve multiple DTMF attempts, audio prompts, and branching paths. |
| Call Engine | The single long-running backend process that owns live calls via ARI/Stasis, runs the game logic, and serves the Operator Console. Replaces the per-call AGI scripts. |
| Operator Console | The web dashboard the Operator uses to monitor calls, switch Modes, rotate Codes, and interact with a live caller (inject audio, trigger easter eggs, force hangup). |
| Talkback | An operator-initiated live two-way conversation: the Booth Phone caller is bridged to the Upstairs Phone so the Operator can speak with the guest, then returned into the game. Resumable, unlike Success. |
| Success Bridge | The reward bridge: caller reaches the Upstairs Phone, Operator drops pizza. Typically terminal. Distinct from Talkback, which is a mid-game detour. |
| Listen-in | The Operator hearing the live caller in the browser console, via an ARI Snoop tap on the call streamed over the WebSocket. Read-only — the caller cannot hear the Operator (unlike Talkback). |
| Call Recording | Every Call Session captured to disk as a mixed track plus separate inbound/outbound stems, keyed to the Call Session ID, for later editing and social media. |
| Live-Call Intervention | An Operator action that reaches into a Call Session already in progress and changes what the caller experiences — force success/exile, force hangup, soundboard, speak-to-caller, Talkback, mode meddling. Distinct from Global Config, which the Operator changes between calls. The boundary between Phase 2 (Eyes) and Phase 3 (Hands). |
| Global Config | Settings that apply to the booth as a whole rather than to one Call Session — the active Mode, the current Code, the Attempt Limit. Writable by the Operator at any time (today via `tools/rotate.py`, in Phase 2 via the Console) and read fresh by each new Call Session. Changing it is not Live-Call Intervention. |
| Handed Off | The terminal state of a winning Call Session: the caller has succeeded and the channel has left the Call Engine for the success dialplan, so the Upstairs Phone ringing, the Operator answering, and the conversation that follows are all invisible to the engine. Distinct from a hangup — the caller won — and shown as such, so the Console never implies the story ended when it didn't. |
| Call State | Where a live Call Session has got to, as the Console renders it: **answering** → **in-mode** → one of the terminal states — Handed Off, Exiled, or hung up. Terminal states are never merged: a win that looked like a hangup would teach the Operator to distrust the panel. A fourth terminal state, *dropped*, is the engine ending the call itself — a failure upstairs, not the caller walking away. |
| Afterglow | The few seconds a finished Call Session stays on the Console before the booth reads idle again, so the Operator sees *how* the call ended rather than a panel that blinks straight back to empty. Display only — the booth is free for the next caller the instant the call ends. |
| Fake PBX | A scripted stand-in for Asterisk that drives the real Call Engine with synthetic Call Sessions, so the Console can be built and demonstrated away from the booth. Development-only; never reachable in a live setup. |
| Console Snapshot | The whole-state message the Console renders from: Global Config plus the live Call Session, or an explicit idle marker when none is. Never a delta — every message is the complete truth, so a browser that attaches late or misses one is immediately correct. Carries a `schema` number, so an old bundle can say it is out of date rather than render nonsense. Distinct from the Config Snapshot, which is per-call and frozen. |
| Call Observer | The second seam out of `core/`, alongside `CallIO`: the game logic telling the *Operator* what the caller is doing, where `CallIO` tells the *caller*. Notified at game-significant moments — attempt started, maze room entered, puzzle drawn — because the flow functions return exactly once, at the terminal outcome, so nothing about a call in progress otherwise escapes them. Optional everywhere, so `core/` stays usable with none. Kept separate from `CallIO` on purpose (ADR-0003): that seam's smallness is why the same logic outlived its driver. |
| Telemetry Socket | The WebSocket carrying Console Snapshots from the engine to every attached browser. Read-only in Phase 2. Gated by the same session cookie as the page; Listen-in audio rides its own socket (ADR-0003). Never silent: a snapshot goes out on a keepalive even when nothing has changed, so a browser can tell a quiet booth from a dead connection. |
| Console Session | A logged-in browser, as an opaque token held in engine memory with a 12-hour expiry. Not a person: the shared password makes operators indistinguishable, and an engine restart ends every session. |
| Off Air | The Console with no Telemetry Socket up. It keeps showing the last Console Snapshot it heard — an Operator wants to know what *was* happening — but dimmed, clock stopped, stamped "last seen" and under an alarm banner, so nothing on screen is claiming to be current. The opposite of an idle booth, which is a stated fact from a live socket. The failure being designed against is not a console that goes blank; it is one that goes on looking fine while the engine is gone, so a broken night reads as a quiet one. Spelled `lost` (the connection) and `stale` (what it is still showing) in code — the two halves the term names together. |
| Config Snapshot | The copy of Global Config taken when a Call Session begins. The whole call is judged against it, so a caller is always scored against the game they were given — an Operator write mid-call lands on the *next* caller, never the current one. |

## Decisions

| Decision | Status |
|----------|--------|
| Core infrastructure (phones, PBX, basic backend) | Done |
| Implementation order | Puzzles first, then backend built to support what proves necessary |
| Audio puzzle attempts | 3 attempts, then Exile message |
| Audio puzzle pool | Multiple puzzles available per day |
| Audio production | Pre-recorded human voice, not TTS |
| Roguelike tree | Infinite maze, no lives, pre-written prompts, tree regenerated per session |
| Roguelike code delivery | Code spoken at end of successful path; caller hangs up and dials it |
| Roguelike prompt delivery | TTS-generated audio, designed to be slightly uncanny for the backrooms aesthetic |
| Silence in a Call Session | An empty DTMF read is the caller having gone, in all three Modes: the Mode tears the call down and the Call Session ends on `hangup`. The Roguelike Phone-Tree used to read silence as an unrecognised key and re-ask the same room forever, which held the engine's one call slot against every later caller until the handset was physically replaced (#53). A key that *is* pressed but is not a choice is still forgiven — the room is replayed and nothing is counted against the caller, so the maze keeps its "no lives or attempt limits". |
| Call logging / persistence | SQLite (stdlib, single file) is the store for Call Session history — core columns (session_id, timestamp, mode, outcome, duration, attempts) plus a JSON column for semi-structured per-mode detail (e.g. roguelike path). Chosen over JSONL because the console's needs are query-shaped (filter, paginate, join to recordings, hunt clips for video) and the switch is ~free while the persistence layer is being rewritten for the engine. Recordings stay as WAV files on disk; the DB holds their paths. |
| Backend language | Python (async / asyncio), driving calls via ARI/Stasis — not AGI |
| Anti-cheese strategy | Defer — trust the experience as deterrent. Physical gatekeeper if needed. |
| Config management | Web dashboard for operator to monitor calls, switch modes, rotate codes |
| Codebase structure | `core/` (channel-agnostic game logic, extracted from the old `agi/`), `engine/` (single asyncio process = ARI app + dashboard WS/HTTP server), `web/` (React + Vite frontend), `tools/` (operator/dev CLIs — code rotation, roguelike playground). `agi/` retired in Phase 1 once ARI proved out (#20); the code-rotation CLI moved to `tools/`. |
| Global Config timing | A Call Session takes a Config Snapshot at pickup and runs entirely against it; Operator writes apply to the next call, never the current one. Fixes existing behaviour where `Router.dispatch()` re-read `mode.json` per attempt, so a mid-call Code rotation could fail a caller for correctly answering the riddle they were played. Config writes also become atomic (temp file + `os.replace`) so a concurrent read can't see a truncated file. |
| Web dashboard auth | Single shared password (one line in config), gating both the HTTP load and the WebSocket upgrade. LAN-only, plain HTTP — mostly runs on the office network. Tailscale added later if remote access is ever needed; never a public port. |
| Web dashboard deployment | Systemd service, specific port. The engine serves the built frontend itself (one process, one port), and `web/dist` is committed to git so the host stays toolchain-free and deploys stay `git pull` + restart — chosen over rsync//host-side builds because event-day ops simplicity outweighs generated files in the repo. Dev uses the Vite dev server proxying `/api` and `/ws` to the engine. |
| Console reconnection | The browser owns recovery. It reconnects on its own — exponential backoff with jitter, capped at 15s so a console left open still notices the engine return, and immediately on a wake, refocus or the network coming back. Whole-state snapshots mean reattaching needs no resync protocol: the next snapshot is the truth. Two engine-side affordances keep it honest. A keepalive snapshot every 20s, because a connection killed by a sleeping laptop often never closes and without a pulse the browser cannot tell silence from death. And `GET /api/session`, because the WebSocket API reports a refused upgrade and an unreachable engine identically while the two want opposite responses — a restart has forgotten every Console Session, so that one ends at the password box, and the other waits. |
| Real-time communication | WebSockets bidirectional between frontend and backend. Live call state reaches the Console as full snapshots on a telemetry socket, fed by a `CallObserver` seam in `core/`; Listen-in audio rides a separate socket opened only while listening. Past-call history is plain HTTP, not the socket. See ADR-0003. |
| Live call telemetry | Most of what the cockpit shows about a live call — Call State, caller ID, Mode, dialled digits — is observed from ARI events the engine already receives, so `core/` is untouched. Attempt number, roguelike room and selected puzzle are the exceptions: they live inside `core.flow` and come out on the Call Observer seam (ADR-0003). The engine's implementation marshals every emission onto the event loop, so a Call Session is only ever mutated there — the Console can never build a snapshot from a session caught half-written. Snapshots carry the call's `started_at` (and `ended_at` once over) rather than a duration, so the browser ticks the clock and a live call doesn't cost a message a second. |
| Console clients | Any number of browsers may have the Console open — the room, not one laptop. Snapshots broadcast to all; commands are last-write-wins with no identity, no locking, and no per-operator attribution (the shared password makes operators indistinguishable by construction). |
| Phase 2 development | Built against a Fake PBX rather than the rig, so the whole stack below Asterisk is exercised at the kitchen table. First ticket of the phase, since every later one is easier once it exists. Listen-in splits on this line: browser playback is developed against synthetic audio frames, and only the Snoop → ExternalMedia half needs hardware. |
| Call audio architecture | Listen-in streamed to the browser (ARI Snoop → ExternalMedia → WebSocket); Talkback via handset bridge to the Upstairs Phone; recording via MixMonitor. See ADR-0002. |
| Recording set | Mixed track + inbound/outbound stems per call, keyed to Call Session ID |
| Talkback browser mute | Auto-mute the browser Listen-in during Talkback — default on, toggleable in the console |
| Consent notice | Deferred — decide later whether to bake a "call may be recorded" line into the intro |
| Call control | ARI/Stasis — a single long-running app owns live calls, enabling async operator interaction and live game-state (see ADR-0001). Replaces the per-call blocking AGI scripts and the earlier AMI-integration idea. |
| Operator interactions | Full v1 power set: speak-to-caller (live TTS), soundboard, listen-in, force success/exile, force hangup, reveal code, mode meddling (roguelike teleport, puzzle swap, live attempt-limit), dead air, Talkback (converse then return to game), rule-based easter eggs |
| Dashboard features | Current state view, mode toggle, code rotation, live call feed, past call logs |
| Console password location | `config/console.json` (gitignored; `console.json.example` is committed) or `PIZZA_CONSOLE_PASSWORD`, which is what the systemd unit uses. Deliberately *not* in `mode.json`: Global Config churns on every code rotation and is read by every call, and a password has no business in a file that churns. With neither set the engine refuses to start rather than serve the Code to the LAN — `--no-console` is the explicit way to run just the phone. Fake mode falls back to a development password, safe because it already refuses to run within reach of a real PBX. |
| Console auth mechanics | The shared password is exchanged for an opaque token held in engine memory (12-hour expiry) and presented as a cookie on both the page load and the Telemetry Socket upgrade. In memory, so a restart logs everyone out and there is no session state to persist or revoke. An unauthenticated page request answers 401 with the *login page* as its body — honest status, usable body — while `/api/*` answers 401 JSON. `/login` and `/assets/*` are public, since a browser must fetch the JS that draws the password box. |
| Console layout | Single-screen cockpit: the current call dominates the center (state, caller ID, duration, live DTMF, node/attempt, Listen-in + level), powers as a fixed control cluster around it, global mode/code in a top bar, past-calls + settings in a slide-over drawer that never hides the live call. Destructive actions (force-hangup/exile) use hold-to-confirm. Backrooms theming deferred to Phase 4. |
| Delivery phasing | Each phase leaves a working phone: (1) Parity + cutover — extract `core/`, ARI engine reproduces the three Modes, flip dialplan `AGI`→`Stasis`, retire `agi/`; (2) Eyes — observation plus Global Config, no Live-Call Intervention: telemetry, past-calls (SQLite), Listen-in, mode/code control; (3) Hands — power set: force success/exile, force hangup, soundboard, speak-to-caller TTS, Talkback, recording; (4) Flair — easter eggs, theming. MVP line after Phase 3. |
